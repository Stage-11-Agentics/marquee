The walkthrough, station by stationTest it in ten minutes

The same loop as the briefing video, in its order. Each station links straight to the surface.

  1. Event settings /settings · organizer
    Conference details, timezone (agenda and calendar invites inherit it), session formats with duration ranges, tracks. Edits save as you make them.
  2. Build a form /forms · organizer
    Five build steps, nine field types, conditional visibility, track routing. Abstracts and Sessions are distinct form kinds — Sessions bypass evaluation. Options bind to Settings, not hand-typed lists.
  3. Open the CFP logged out /f/cfp · no seat
    A real server-rendered page — the form is in the HTML. Try it in a private window.
  4. Submit as a speaker same page
    Validation fires on blur and again on the server; drafts autosave with a private resume link; the headshot shows a crop preview before submit. The confirmation keeps the resume link and offers the speaker portal.
  5. See the speaker's side enter as speaker
    Acceptance status ("Accepted · Wave 1"), the scheduled slot with room, building, address and an arrival plan, per-role confirmation, self-managed bio, and the onboarding task list — hotel & travel first.
  6. Set up evaluation /evaluation · organizer
    Rounds each with their own scorecard, reviewer pools, 3-per-submission distribution, anonymous toggles, results with per-criterion CSV export — and Agent evaluator seats: a reviewer identity you can hand to an AI, with its own credential, prompt, and rubric.
  7. Evaluate enter as reviewer
    A track-scoped queue. Approve / Maybe / Deny is the primary path (keyboard: A M D, 1–5, Enter); the weighted scorecard is optional depth. Declare-conflict recuses. Out-of-scope requests 403 — the scoping is real.
  8. Push accepted sessions to the agenda /agenda-builder · organizer
    Drag from the unscheduled tray; format defaults set duration; no save button. List, day, week, track, room views. Room, double-booking, and building-transit conflicts warn live. Publishing is a review gate that lists exactly what goes public.
  9. View the public program /agenda · /speakers · no seat
    Day tabs, filters, session pages with add-to-calendar, the speaker directory, an embed builder with copyable code — and attendees can star sessions into a personal schedule with a shareable link and calendar feed. No account.

The brief, item by itemSix asked, three struck — honestly graded

Brief itemStatusSee it / the honest note
1 · CFP forms with conditional logic & category routing SHIPPED /forms · /f/cfp. Gaps: no WYSIWYG, no section headers — plain fields with character budgets.
2 · Self-service speaker portal SHIPPED speaker seat. Gaps: no pronouns field, no admin↔portal impersonation.
3 · Templated comms + calendar invites (Gmail/Outlook/iCal) SHIPPED /communications. 13 lifecycle templates; ICS with request, update (SEQUENCE), and cancel. Demo mail is sandboxed by design — full renders visible, nobody real gets mailed.
4 · Evaluation & scoring, multi-round SHIPPED /evaluation. Rounds with per-round scorecards, committees, pools, blind review, comparison mode, track scoping. AI-assisted review deliberately not built.
5 · Drag-and-drop agenda, conflict detection, five views SHIPPED /agenda-builder. All five views including track — the one the incumbent lacks. Three conflict classes: room, speaker, building transit.
6 · Real-time dashboard of outstanding speaker tasks SHIPPED /onboarding. Speaker × task matrix, severity-ordered, nudge in place. The incumbent's answer is a weekly digest email; the other tool has no task system at all.
7 · Accelevents integration NOT BUILT Skipped per the ruling. The seam (REST API + import boundary) is documented as an extension point.
8 · Portal resource / wiki pages NOT BUILT Struck in the brief; not built.
9 · Embeddable gallery & schedule BUILT ANYWAY Struck, but the video wants it — so: an embed builder, saved embeds with a kill switch, 30-second freshness (the incumbent refreshes hourly).

The bonusesThree claimed, two forfeited on purpose

  • Cloudflare — one Worker: D1 source of truth, R2 uploads, KV cache, four Queues. The live site is the README's own deploy sequence.
  • API — 195 operations the admin UI itself runs on; live OpenAPI 3.1 + rendered reference; scoped tokens; a 48-command CLI and an agent skill file in the repo.
  • Speed — server-rendered public pages answer in ~a quarter second; the register renders ~1,000 real rows. Measure it: curl -so /dev/null -w '%{time_starttransfer}\n' https://marquee.stage11.dev/agenda
  • Airtable — not claimed. D1 stays the source of truth at 1,000+ submissions; an async Airtable mirror is a designed extension point, not a shipped feature. We forfeit the bonus rather than fake it.
  • Forge hosting — not claimed. The repo is on GitHub.

Beyond the briefEight things nobody asked for

Each checkable in under a minute.

The UI is a client of its own API

A route can only exist with its OpenAPI contract attached — a UI-only feature is structurally unwritable. 195 operations, none privileged.

/api/docs

Content-addressed API docs

The OpenAPI document's ETag is the SHA-256 of its own bytes — docs-match-code, provable with curl.

curl -s …/api/openapi.json | shasum -a 256 vs the ETag header

A 48-command CLI + agent skill file

The whole operating loop as dependency-free commands; SKILL.md is generated from the CLI and gated by a test that fails if it ever needs curl. Four operator screens carry a "Hand this to your agent" brief.

node cli/marquee.mjs --help

Demo-safe mail

Press Send anywhere — bulk included. Non-allowlisted addresses render and log but are never delivered. Judging a comms product shouldn't require restraint.

/communications

The "decided but not told" number

The dashboard counts decisions whose speakers haven't heard yet — hundreds in the demo — one click from the compose flow that fixes it. Nobody else computes this.

/dashboard

Reversal is designed

Un-accepting enumerates everything it touches — tasks, queued mail, calendar invites — cancel-or-retain per item, attributed history, real ICS CANCEL.

accept → un-accept any submission as organizer

Transit conflicts

The venue model knows buildings as places. "Leave by 4:00 PM" is computed from the speaker's own previous session — a third conflict class no competitor models.

/agenda-builder · speaker portal arrival plan

Never phones home

No vendor SDK, no analytics, no telemetry. A speaker's email cannot be logged — the log builder has no field for it. Allowlist, not scrubbing.
