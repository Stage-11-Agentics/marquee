## The two rules most likely to be broken here

1. **Airtable is never read on a request path (G4).** This is US-72's non-negotiable and the
   whole reason the 60-second budget in AC-225 can coexist with R7's speed requirement instead
   of fighting it. You own the enforcement, not just the compliance: ship the **import-boundary
   check** that fails any import of the Airtable client from outside `src/jobs/mirror/*`. The
   cancelled MRQ-46 was the audit that would have checked for this; it is folded into your
   ticket deliberately, because a guardrail that ships with the code it guards cannot be skipped
   for capacity.
2. **`reset:demo` must short-circuit the change feed.** It writes with a `suppress_mirror` flag
   so **no** per-row outbox entry is enqueued, then enqueues **one** reconcile job at the end.
   §3.9 does the arithmetic: without this, one reset queues ~1,000 submissions plus speakers and
   tasks and drains for 25s+ of Airtable traffic. `reset:demo` already enqueues exactly one
   reconcile message today — the stub-ack at `src/index.ts:249` is where the real consumer lands.

## Absent configuration must disable the mirror cleanly

With no `AIRTABLE_API_KEY` and no configured base: the change feed does not accumulate, the
consumer no-ops, nothing errors, nothing retries into a queue backlog, and nothing appears
half-built. **A Marquee with the mirror switched off must be indistinguishable from today's
Marquee.** That property is what lets this land before a base exists, so treat it as an
acceptance criterion and write a test for it. Today's product is the baseline: if your branch
changes any behaviour that a user can see while unconfigured, you have broken this rule.

Also update the `check:mirror` stub message so it names the missing **base** rather than a
missing implementation — after you, the implementation is not what is missing.
