`0006_audit_log_request_id.sql`, `src/lib/audit.ts`); `src/lib/history.ts` and
`src/ui/history/ContentHistory.tsx` already project history somewhere — study both before
writing a line. If you find yourself creating a second event table, stop and re-read.

Three lenses:
1. **Org admin lens** — reverse-chron admin actions (invites minted/claimed/revoked, member
   removal with what was revoked, token create/revoke, org default changes, ownership
   transfer). Instrument the writers that exist on main; for writers MRQ-207/MRQ-212 are
   building in parallel, expose one named recording seam they can call and note it in the
   PR + a ticket comment on 207/212.
2. **Person lens** — the person record's activity feed merges audit rows touching that
   person with existing annotations/history (the CRM drawer's feed shape in
   `prototypes/crm/index.html`).
3. **Submission lens** — a timeline on the submission record: submitted, routed, reviewed,
   decided, reversed, re-accepted, mail sent — author + timestamp each. This is the "why is
   this talk in this state" answer; extend the existing history machinery.
