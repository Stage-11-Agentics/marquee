## Context you need before you start

**This is a seat, not a screen.** The reviewer is the only role in Marquee whose entry
point is a work surface rather than a place. The organizer gets `/dashboard`; the speaker
gets `/portal` with tasks, profile and talks; the reviewer gets dropped onto submission #1
with the scorecard already open and an "Exit queue" button that calls `history.back()` and
lands nowhere. Atin's words, 2026-08-13: *"here's your queue, here's your attributes,
here's where you edit your profile — and then when it's time to review a specific item,
then you enter the queue."*

**Almost nothing new is needed underneath.** The queue payload already returns the plan,
the round with its mode and `anonymized` flag, the reviewer's track `scopes`, counts, and
the `completed` list with each recorded review. `evaluation_rounds.closes_at` exists in
`migrations/0001_init.sql`. `PATCH /api/v1/me/profile` is `auth: { kind: "authenticated" }`
— not speaker-gated — so a reviewer can already edit their own profile through it, and
`ProfileForm` in `src/ui/portal/PortalPage.tsx` already renders exactly that form. The one
genuine addition is committee membership on the queue payload. If you find yourself
writing a second endpoint, stop and re-read.

**Marquee is a design-bound build.** `DESIGN.md` is the binding design language (Flight
Deck; tokens in `prototypes/skins/skin-c.html`) and `PHILOSOPHY.md` binds the copy. The
reviewer surface has its own topline deliberately — no organizer sidebar on either page.
Match the existing `review.css` idiom rather than inventing a new one, and read
`src/ui/portal/PortalPage.tsx`'s panel structure, which is the closest existing precedent
for what home should feel like.

**One UI rule that is easy to violate here:** elements never jump. Toggling profile edit
open, or the queue going from 24 waiting to 23, must not move anything below it. Reserve
space, use tabular numerals for counts, keep row counts constant.
