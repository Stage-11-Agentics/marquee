## 1. Verdict

Assembling from any tree that contains the new tooling (i.e., master, the moment this merges) produces a public snapshot whose `scripts/checks/assemble-public.mjs` and `tests/node/assemble-public.test.mjs` are syntax-broken, so the public repo's `npm test` dies on load and the public repo cannot re-run its own assembly. ## 3. Issues

**[CRITICAL] scripts/checks/assemble-public.mjs:179 — Scrub rule corrupts the assembled tree's own tooling**
The rule `/sequence\/research\/[^\s)`>]+/gi → "the public product contract"` does not stop at quote characters, and the public allowlist now includes this very file plus its test — both of which contain literal `"sequence/research/…"` strings (`PUBLIC_EXCLUDED_PATHS` at lines 62–86, `SOURCE_PROGRAM_PATH` at line 88, and the fixture paths throughout `tests/node/assemble-public.test.mjs`). The match consumes the closing quote (and trailing comma/semicolon), producing unbalanced string literals. Reproduced: running `node scripts/checks/assemble-public.mjs --repo . --ref HEAD --output <tmp>` on this branch yields an output where both files fail `node --check` (`"the public product contract` at assemble-public.mjs:64 onward). The rehearsal orphan `9a3b3045…` cited in the validation artifact contains the same broken files, so the gate-16 rehearsal evidence is unsound: the rehearsed public snapshot ships code that cannot parse, and the public repo's numbered clean-checkout path (README promise, plan Phase 3.5) fails at `npm test`.
**Fix:** Apply the split-literal discipline already used everywhere else in this file (`joinParts`/array-join, as done for `lattice`, `stage11`, `Forgejo`) to every `sequence/research` and `sequence/USER_STORIES` literal in `assemble-public.mjs` and `assemble-public.test.mjs`, so no scrub rule can match the tooling's own source. Independently, harden the two path rules (lines 178–179) to stop at quotes: `[^\s)"'`>]+`. Then add the missing regression: after assembly in the test, run `node --check` (or a syntax parse) over every `.mjs`/`.ts` in the output — that single assertion would have caught this.

**[MAJOR] scripts/checks/assemble-public.mjs:297 — `writeCommit` embeds the operator's private identity in the public commit**
`git commit-tree` inherits ambient repo config, so the rehearsal orphan `9a3b304` was authored as `Atin <atin@atin.me>` — a real personal email in the commit metadata of a would-be-public artifact. `check:repo` cannot catch this: its content scan runs `git log --format= -p`, which omits author/committer headers, and its email rule only sees blob content. The original orphan `f424064` avoided this only because it was created manually with `Marquee <marquee@example.com>`; the reusable tool re-introduces the leak for every future assembly.
**Fix:** In `writeCommit`, set an explicit public-safe identity (`GIT_AUTHOR_NAME/EMAIL` and `GIT_COMMITTER_NAME/EMAIL` in the env passed to `commit-tree`, e.g. `Marquee <marquee@example.com>`), and extend `check-repo.mjs` to scan `git log --format='%an %ae %cn %ce'` of the publish ref against the email/content rules so the gate itself would have flagged it.

**[MINOR] scripts/checks/repo-policy.mjs:34 — Email allowlist lookahead is bypassable by crafted domains**
In `(?:[A-Z0-9-]+\.)*(?:example|invalid|test)(?:\.(?:com|net|org|invalid|test))?\b`, the optional TLD group can be skipped and `\b` matches at `example|.`, so `user@example.evil.com` (and `user@test.anything.tld`) satisfies the "safe" lookahead and is not flagged as a real email. The scrubber's variant in `assemble-public.mjs` (line ~176) has the same shape with `(?:\.[A-Z]{2,})?` and the same bypass. Low likelihood in this repo's content, but this is a fail-closed policy file.
**Fix:** Anchor the safe-domain alternative to end-of-domain instead of `\b`, e.g. require the whole domain to match: `@(?!(?:[A-Z0-9-]+\.)*(?:example|invalid|test)(?:\.(?:com|net|org|invalid|test))?(?![A-Z0-9.-]))…` — i.e., add a negative lookahead for further domain characters after the safe suffix. Also consider extracting the one regex into `repo-policy.mjs` and importing it from the assembler so the two definitions can't drift (they already differ).

**[MINOR] scripts/checks/check-repo.mjs:28 — Historical path walk is blind to files introduced only in merge commits**
`git log --full-history --format= --name-only` lists no paths for merge commits (no `-m`/`--diff-merges`), so a file added solely by an evil merge and later deleted would evade `DENIED_HISTORY_PATHS`. The union with `ls-tree` covers the current tree, and every branch-side commit in this repo's PR history does surface its paths, so exposure today is theoretical — but this checker's whole reason for existing (per plan-review resolution 2) is closing enumeration blind spots.
**Fix:** Add `--diff-merges=first-parent` (or `-m`) to the log invocation; output volume is the only cost, and `MAX_BUFFER` already accommodates it.

**[MINOR] scripts/checks/assemble-public.mjs:317–323 — `--force` deletes an arbitrary pre-existing output directory**
`assertSafeOutput` only refuses the repo root, its parent, and `/`. With `--force`, any other populated directory passed as `--output` (a typo'd `~/Documents`, say) is `rm -rf`'d wholesale. For a tool intended to be run under deadline pressure at 21:00 on ship night, that's a sharp edge.
**Fix:** On `--force`, only delete contents the assembler recognizes (e.g., require the directory to be empty or to contain a marker file written by a prior assembly run), or refuse `--force` when the target lies outside the system temp directory and the repo's parent workspace.
