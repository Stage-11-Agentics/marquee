## Judgment calls

- The policy will use only origins discovered from the repo and live deployment configuration. If the repo has no separately documented local origin, use the actual Vite dev origin confirmed from `vite.config.ts`/the dev command, not a wildcard or an invented hostname.
- The apply mechanism will use the least-privileged Cloudflare/R2 interface already supported by the installed toolchain. It will fail closed when required environment variables are absent and will never commit credentials. The operator has explicitly authorized applying the policy to the real `marquee-media` bucket; if MRQ-89's scoped credential cannot set bucket CORS, document that exact permission blocker in the PR and Lattice rather than widening it.
- The preflight check already exists and is binding scope: retain its production, required-header, and wrong-origin assertions rather than creating a parallel check.
- A preview-bucket policy is in scope only if repository bindings/routes or live upload URLs prove that browser uploads use it; otherwise the single `marquee-media` policy is the correct narrow fix.
- The user-facing failure sentence will be stable and human-readable, with a visible Retry control that reuses the existing file/task attempt path. The precise low-level failure remains a console diagnostic.

## Scope and non-goals

- In scope: R2 browser-upload CORS policy and idempotent apply path, its slow integration/deploy-check coverage, the speaker-facing upload failure/retry presentation, and local browser evidence/documentation. Applying the policy to the real bucket is authorized infrastructure configuration; deploying the Worker is not.
- Out of scope: unrelated live-site defects, upload authorization/credential widening, data-model changes, a new upload transport, public repo assembly, automatic deployment wiring, or merging the PR.
