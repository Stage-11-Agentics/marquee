# KYS-3: Local uploads: worker-served PUT door so file fields work without Cloudflare credentials

Found by the sbek eval run 2026-08-11: 18 of 22 scenarios burned to the 70-turn cap because the public CFP headshot (and every other file field) can never complete locally — the presigner signs against the real R2 S3 endpoint with the deliberately fake local credentials (MRQ-14), so the browser PUT dies on the wire, the field stays unanswered, and the form cannot be submitted. Scored as a critical defect in four of seven eval areas. Fix: LOCAL_DIRECT_UPLOADS=1 (same house pattern as INSECURE_LOCAL_COOKIES) makes the sign routes return a worker-served PUT URL; the worker validates a purpose-tagged HMAC token, declared content-type, and exact byte count, writes to the local R2 binding, and the unchanged complete-and-verify pipeline (magic bytes, size, dimensions) runs as in production. Prod is byte-identical when the flag is unset: presigning untouched, the direct-put door 404s, app-host media stays 404. The signer's hardcoded endpoint (trap 9) is deliberately not made configurable. Covered by an end-to-end test in tests/unit/r2/uploads-routes.test.ts.
