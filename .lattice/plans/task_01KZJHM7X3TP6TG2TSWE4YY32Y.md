Operational build/type checks in CI invoke `npx tsc --noEmit` and `npx vite build` directly so the owned script table remains the thirteen contractual commands.

Shared harness infrastructure:

- `scripts/checks/lib/command.mjs` provides structured console output, wall-clock timing, required-argument/environment validation, report writing, and an explicit `stub` result. A stub prints command name, owning future ticket/capability, missing preconditions, and replacement contract. ### 5. Fast and slow suite separation

`npm test` is the fleet's inner-loop clock. It includes pure functions, Hono handlers against Miniflare/local D1, queue logic with in-memory/stub providers, token/route/component logic that can execute without a browser, and small fixed fixtures only. A test that needs any excluded resource belongs in the named slow command above; raising the 30-second limit is not an option.

CI in `.github/workflows/ci.yml` is layered:

- The required PR job uses a pinned Node version, `npm ci`, direct TypeScript/build checks, `verify-design-contract.mjs`, `npm test` with an independent elapsed-time assertion, and `npm run trace:ac -- --scope=merged`. It uploads reports on success/failure and has no service credentials.

Stub status, missing report, skip, or missing precondition fails the gate. Objective-only speed misses remain uploaded warnings; AC-sourced misses fail.
- Cache dependencies, not test state or seed data. Use workflow-level timeouts at the command budgets. Keep provider/secret contexts out of fork/untrusted PR jobs.
