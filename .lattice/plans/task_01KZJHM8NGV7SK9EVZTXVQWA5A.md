## Architecture and owned files

Keep production code inside the ticket surface, with exact names adapted only to merged conventions:

- `src/routes/uploads.routes.ts` — M-07 route definitions and handlers for public, speaker, and authorized event/submission sign/complete operations; public ready-media GET on the media host; file delete/replacement hooks where M-07's frozen file-lifecycle contract requires them.
- `src/lib/r2/policy.ts` — owner-specific extension/MIME/size/dimension policy, safe filename handling, and the one policy decision used by both handlers and clients. Documents use the task/form `accept[]` and `maxBytes` configuration, bounded by the contract's 100 MB absolute ceiling; headshots allow JPEG/PNG/WebP and carry a deliberately stated minimum dimension. No SVG or generic ZIP fallback.
- `src/lib/r2/keys.ts` — opaque, non-user-controlled object keys and stable public URLs. Keys contain event/attachment partitioning plus fresh random entropy; raw filenames never choose a path. `publicMediaUrl` accepts only a `ready` R2-backed attachment and always returns `MEDIA_PUBLIC_ORIGIN`, never an Airtable URL.
- `src/lib/r2/presign.ts` — SigV4 PUT signing using Cloudflare's documented `aws4fetch` pattern and short expiry (10 minutes). It constructs only `https://{R2_ACCOUNT_ID}.r2.cloudflarestorage.com/{R2_BUCKET_NAME}/{encoded-key}`; it rejects any configured endpoint whose parsed hostname is not exactly the account S3 endpoint. The signature pins `Content-Type`, immutable attachment metadata, and `If-None-Match: *`; the browser must send the returned signed headers exactly. The conditional makes a still-live bearer URL unable to replace bytes after successful completion.
- `src/lib/r2/upload-client.ts` — a framework-neutral `XMLHttpRequest` PUT helper, because XHR exposes upload progress. It accepts the server-returned URL/headers, reports monotonic byte progress, supports abort, and allows retry with the same `File` without clearing caller form state. A 403/expired URL requests a new presign rather than falling back to an app/custom-domain PUT.
- `src/lib/r2/sniff.ts` — bounded ranged reads and fail-closed classification: PDF signature; PNG signature/IHDR dimensions; JPEG signature plus bounded SOF scan; WebP RIFF/WEBP chunk and dimensions; PPTX/KEY ZIP container signatures plus their expected archive manifest entries. A generic `PK` prefix is not enough to relabel an arbitrary ZIP as PPTX or KEY. Unreadable/truncated/ambiguous containers fail closed without buffering a large object in Worker memory.
- `src/lib/r2/complete.ts` — HEAD/metadata/size verification, bounded sniff, ready transition, and mismatch cleanup. It is idempotent and narrows `pending -> ready` with a conditional D1 update. Missing/incomplete objects remain pending and retryable; declared-size, metadata, extension/MIME, magic-byte, or image-dimension mismatches delete the R2 object immediately and remain non-ready for retry/sweep. The signed `If-None-Match: *` closes the HEAD/sniff-to-ready overwrite race.
- `src/lib/r2/rate-limit.ts` — KV counters with separate HMAC-pseudonymized IP and submission/draft keys, fixed windows/TTL, and standard 429 headers via M-07. Verify Turnstile and authorization before touching counters; then require both counters before inserting the pending row or signing. Keep limits in one exported policy table and cover exact boundary/reset behavior. KV's documented eventual consistency means these are abuse caps with bounded slop, never authorization.
- `src/lib/r2/serve.ts` — host-gated ready-object streaming from `MEDIA`. The app host returns 404 for the media route; only the configured separate media origin serves. Responses force `Content-Disposition: attachment` with a sanitized filename, `X-Content-Type-Options: nosniff`, a verified content type, ETag/cache policy, and no credentials/cookies. Raw or `pending` objects are never served.
- `src/lib/r2/images.ts` — stable headshot derivative URLs/config for Cloudflare Images over the R2-backed media origin. R2 remains canonical; variants are decoded/re-encoded derivatives and raw originals retain attachment disposition. The crop/variant contract is reusable by MRQ-16 and does not upload a second canonical copy into Images.
- `src/lib/r2/orphan-sweep.ts` — nightly batched query of `pending` rows older than 24 hours, idempotent R2 delete followed by D1 row cleanup, with bounded batches and structured counts/errors. It never lists R2 and never runs on a request path.
- Colocated focused tests using M-06's Miniflare/Vitest pool and `tests/ac-claims/MRQ-14.json`. Do not add package scripts or a separate deployed test harness.

## Request and object lifecycle

1. Normalize the requested owner (`person_headshot`, `task_upload`, `event_logo`, or `import_file`) and resolve it server-side. Public uploads require a valid, event/field-scoped draft or resume capability plus a fresh Turnstile token. Speaker/admin/API uploads require the merged session/bearer principal and exact event/person/submission/task authority; because the ticket says every presign, the handler also applies the merged Turnstile presign policy rather than inventing an exemption.
2. Verify Turnstile server-side first, including expected hostname/action where the verifier exposes them, then verify owner scope. Missing, replayed, invalid, unauthenticated, and out-of-scope requests stop here with no mutation and no signer call.
3. Validate extension, declared MIME, configured `maxBytes`, non-zero size, and owner policy independently. Enforce both KV caps. Create one `pending` attachment row with a random immutable key and declared metadata, then generate a 10-minute PUT URL against the S3 API origin only. If signing fails, remove the just-created pending row so no phantom grant remains.
4. Return `{attachmentId, putUrl, requiredHeaders, expiresAt, completionToken}`. The completion capability is short-lived and HMAC-bound to attachment/owner/key; no raw credential or R2 account secret leaves the Worker. Treat the presigned URL itself as a bearer secret and never log its query string.
5. The browser performs a direct PUT to R2 with the exact signed headers and XHR progress. It never uploads through the Worker and never substitutes `MEDIA_PUBLIC_ORIGIN` or the app origin. `If-None-Match: *` means retry after an uncertain first success can return 412; the client then calls `/complete`, which HEADs the object and resolves authoritative state instead of uploading over it.
6. `/complete` authorizes the same owner/capability, loads the pending row, and uses `MEDIA.head(r2_key)` to verify existence, exact byte count, signed metadata/content type, and immutable object identity. It then range-reads only the bytes needed for magic/container/dimension detection. Client MIME and extension are hints, never proof.
7. On any type/size/dimension contradiction, delete the object, confirm `MEDIA.head(key) === null`, return a typed 4xx, and leave no ready URL. On success, atomically mark the D1 row `ready` with verified MIME/size/checksum data and return only the stable separate-origin public URL plus headshot derivative URLs where applicable. A repeated completion returns the same ready representation.
8. Deletion is scope-checked and idempotent. Replacement always creates a new attachment/key/version, updates the owning record only after the new object is ready, then deletes the old object; a presigned URL never overwrites a ready canonical key.
9. The nightly scheduled hook runs the 24-hour orphan sweep. Partial failures are safe to retry: missing R2 objects are treated as already deleted, while a failed R2 delete prevents premature D1-row removal.

## Trap prevention and non-goals

- **Trap 9:** signing code has no custom-endpoint option. A unit/static assertion parses every returned PUT URL and requires `{account}.r2.cloudflarestorage.com`; `MEDIA_PUBLIC_ORIGIN` appears only in read/variant URL helpers.
- **Trap 10:** R2 is the only canonical byte store. `attachments.r2_key` plus the stable public R2 media URL are the only outbound media representation; Airtable integration later receives that public URL and never contributes a URL back into serving, headshots, or D1.
- **Untrusted type:** sign-time extension and MIME checks are independent; completion always HEAD-verifies and magic-byte/container-sniffs. A mismatch deletes the object and proves HEAD 404 before the rejection test passes.
- **Abuse:** Turnstile/scope gate precedes all side effects, KV has distinct per-IP and per-submission/draft caps, object keys are random, grants expire quickly, completed keys cannot be overwritten, and 24-hour pending objects are swept.
- **Origin isolation:** media GET is accepted only on `MEDIA_PUBLIC_ORIGIN`, never the app host, and always forces attachment plus `nosniff`. CORS permits browser PUT only from the configured app origin and only for the exact signed headers/method.
- **No malware scanner:** AV is deliberately not implemented. Keep a short extension-point note colocated with the media safety module for M-45/README consumption; do not add a fake scan state or weaken attachment/origin isolation.
