# Direction: The Pipeline

**Read `prototypes/PROTOTYPE-CONTRACT.md` first — it is binding. This file is what makes your take different.**

## Core assumption

The primary user is the **program lead**, and the product *is the lifecycle*: submissions flowing CFP → review → waves → schedule → published. If the pipeline is legible and fast, every seat's work falls out of it. This is also the judge-optimal shape: driving the demo is literally driving the walkthrough video.

## Home surface

The **program pipeline dashboard**: the lifecycle rendered left-to-right as stages (Submitted → In Review → Waved → Accepted → Scheduled → Published) with live counts, every number clickable into the filtered list behind it. Below: attention strip ("Wave 2 in 6 days · 214 unreviewed in Agents track · 9 speakers overdue"), each item a deep link. The nav mirrors the lifecycle order exactly.

## Signature moves (must actually work)

1. **Clickable pipeline**: click any stage count → the filtered submissions list, instant, with bulk actions (select filtered set → "Accept 37" → status cascade preview: emails queued, portals updated, invites offered).
2. **The submissions list at 1,000 rows**: filter/sort/search that feels instant; status chips; bulk select; this screen is where the speed thesis lives or dies.
3. **Wave planner**: a small panel showing the three waves with counts and dates; accepting mid-CFP visibly moves the numbers.

## Aesthetic & voice

**Modern SaaS clarity, Linear-grade.** Generous whitespace over a crisp grid; a single confident accent color; typography-led hierarchy; subtle 120ms transitions that make speed *legible*; empty states that teach. Voice: clear and quietly confident — the interface narrates state ("Wave 2 closes Friday — 214 abstracts still unreviewed"), never chirps.
